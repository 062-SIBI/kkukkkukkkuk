# 아이폰 산책 카드(라이브 액티비티) 설계, 0.5.1

작성 2026-11-23. 상태: 1판은 06 승인(11/23 저녁). 2판은 검토 회의(아스트라, 11/23 밤)와 06 답을 반영했고 06 확인을 기다린다.

## 한 줄
산책하는 동안 아이폰 잠금 화면과 다이내믹 아일랜드, 애플 워치에 작은 산책 카드(걸은 시간, 거리, 강아지가 든 산책 링, 똥 | 킁킁 | 꾹 버튼)를 띄워서, 목줄을 잡은 채 앱을 열지 않고 한 손으로 기록하게 한다.

## 왜 (06의 말과 이미 정한 것)
- 06(11/23): "어플 냈으니까 위젯 만들자". 세 안 가운데 C를 고르며 "버튼까지, 가능하면 조그맣게 PiP처럼 계속 화면에 뜨는 버튼이 있으면 좋고". 범위는 "아이폰 먼저".
- 아이폰은 다른 앱이 아무 화면에나 떠 있는 버튼을 띄우는 것을 허락하지 않는다(PiP는 영상 전용). 그래서 아이폰에서 가장 가까운 모습인 다이내믹 아일랜드와 잠금 화면 카드로 한다(06에게 설명하고 '아이폰 먼저'로 답을 받음).
- 06(11/23 밤, 회의 결과를 보고): 카드로 누른 똥은 "미확인", "캐릭터는 못 넣제?", 워치와 맥에 횟수가 보여도 "좋아", "워치 연동되게 만들고 워치로 정확도 올릴 수 있는 건 올리고 워치용 버튼도".
- 프로젝트 원칙: 기록은 3초 안에, 산책 중엔 목줄 잡느라 한 손이다. 10/26 안드로이드 위젯(위에 km와 걸은 시간, 아래 로고 점 셋 버튼)과 같은 쓰임이다.
- 11/19 06 결정: 위젯과 사진의 링은 숫자 없이 링만. 산책 화면 링 안에는 꾸밀 수 있는 강아지(캐릭터).
- 11/20 06 결정: 아이폰 위젯은 다음 판(지금이 그 판).

## 목표
1. 산책을 시작하면 잠금 화면과 다이내믹 아일랜드에 산책 카드가 뜬다.
2. 카드에는 걸은 시간(초 단위로 흐름), 거리(km, 소수 한 자리), 산책 링(앱 산책 화면의 링과 같은 값, 숫자 없음), 버튼 셋이 있다. 버튼은 앱 산책 화면과 같은 순서(왼쪽부터 똥, 킁킁, 꾹), 같은 색(코랄, 노랑, 파랑), 같은 아이콘이다.
3. 카드의 버튼을 누르면 지금 산책에 기록된다. 앱 산책 화면의 버튼을 누른 것과 같은 결과이고, 똥의 굳기만 '미확인'이다.
4. 산책을 끝내면 카드가 끝난 모습으로 바뀌고 5분 뒤 사라진다.
5. 애플 워치(watchOS 11 이상)의 스마트 스택에도 작은 카드(시간, 링, 버튼 셋)가 떠서 손목에서 바로 누른다. 워치 앱 없이 라이브 액티비티의 워치용 모습으로 한다.
6. 링 안에 앱 산책 화면과 같은 강아지(꾸민 모습, 같은 자세)가 보인다. 마지막 단계에 넣고, 늦어지면 카드를 먼저 내고 강아지는 0.5.2로 미룬다.
7. 아이폰 0.5.1로 테스트플라이트에 올려 06 아이폰과 워치에서 확인한 뒤 앱스토어 심사를 낸다.

## 실패로 보는 것 (돌아가도 이러면 실패)

- 폰 밖으로 새로 나가는 정보가 생긴다(06 본인의 워치와 맥에 애플이 보여 주는 것은 빼고, 06 승인 11/23 밤)
- 안드로이드와 웹이 지금과 다르게 움직인다(위젯과 카드로 누른 똥의 굳기 '미확인'만 빼고. 안드로이드 위젯 코드는 아직 합치지 않아 쓰는 사람이 없다)

## 제약
- 아이폰 프로젝트는 빌드마다 새로 만든다(.github/workflows/ios.yml: `npx cap add ios` 다음 `ios-kit/patch-ios.js post`). 위젯 익스텐션 타깃은 프로젝트를 만든 직후 한 번만 붙인다. 출시 단계는 그 프로젝트를 다시 쓰므로 다시 붙이지 않는다(회의 4).
- 출시용 보관 빌드는 서명 없이 만들고(CODE_SIGNING_ALLOWED=NO), 내보낼 때 App Store Connect API 키로 클라우드 서명한다. 위젯 익스텐션은 새 번들 아이디(앱 번들 아이디 뒤에 이름을 붙인 것)가 필요하다. 클라우드 서명이 이 아이디를 자동으로 등록하고 프로비저닝하는지는 첫 테스트플라이트 빌드에서 확인한다. 안 되면 06이 애플 개발자 사이트에서 아이디를 한 번 등록한다(로그인과 입력은 06, 순서는 Claude가 적음).
- 라이브 액티비티는 iOS 16.2 이상(ActivityContent 기준으로 통일), 카드 안 버튼은 iOS 17 이상이다. 16.2~16.x는 버튼 대신 횟수를 읽기 전용으로 보인다. 그보다 낮은 iOS는 카드가 없고 앱은 지금처럼 쓴다. 앱의 최소 iOS는 바꾸지 않는다(회의 10).
- 카드 값은 갱신마다 4KB를 넘을 수 없다(애플 ActivityKit 문서). 강아지 그림을 PNG로 넘기면 66~84px에서 base64 3.6~5.2KB라 넘는다(11/23 앱 그림으로 잼). 그래서 익스텐션이 그림을 직접 그린다.
- 잠긴 아이폰에서는 카드 버튼이 인증 뒤에 동작한다(애플 문서). 워치는 손목에서 풀려 있어 따로 인증하지 않는다.
- 워치: 아이폰 라이브 액티비티는 워치 앱 없이 스마트 스택에 뜬다. 기본은 작은 아일랜드 모습이고, `.supplementalActivityFamilies([.small])`를 주면 워치용 모습을 따로 그린다(`activityFamily`가 `.small`, WWDC24 10068). 워치에서 버튼이 눌리는지는 애플 포럼 답(watchOS 11 베타 3에서 고침, 2024년 7월)만 있어 06 워치에서 확인한다(미확인).
- 맥: macOS 26 이상에서 아이폰 미러링을 켜 둔 맥은 메뉴 막대에 작은 모습이 뜨고, 누르면 아이폰 미러링으로 앱이 열린다(애플 지원 문서 120684). 따로 만들 것은 없다.
- 기록은 폰 안에서만 오간다.
- 일정: 2라운드 서류 마감(12/1 13:00)이 먼저다.
- 저장소 규칙(AGENTS.md): PR로 올리고 합치기는 06, 화면 글은 한국어로 짧게, 줄표 문자 쓰지 않기, 고친 뒤 Playwright 시험, 종량제 API 키 쓰지 않기. 묽은 변 경고가 바뀌는 것은 P1이라 PR에 따로 적는다.

## Claude가 정한 것 (06이 되돌릴 수 있음)
1. 버튼은 아이콘, 이름, 이번 산책 횟수를 44pt 이상인 한 칸으로 묶는다(회의 7). 점수는 보이지 않는다.
2. 누른 칸은 5초 동안 체크와 '되돌리기'로 바뀌고, 누르면 그 눌림 하나를 취소한다(회의 6). 카드에 미리 올린 횟수는 늦게 온 예전 갱신이 줄이지 못하고 되돌리기로만 줄어든다.
3. 다이내믹 아일랜드: 작은 모습은 왼쪽에 강아지와 걸은 시간(강아지를 넣기 전에는 앱 색 점 셋), 오른쪽에 작은 링. 가장 작은 모습은 링만. 펼친 모습은 시간과 링을 양옆에, 거리와 버튼을 아래에 두고 카메라 자리는 비운다(회의 8).
4. 잠금 화면: 시간, 거리, 링(강아지)이 위, 버튼 셋이 아래. 기준을 배우는 중에는 점선 링과 '평소 산책을 알아가는 중' 한 줄(회의 10).
5. 워치: 시간과 링(강아지)이 위, 작은 버튼 셋이 아래. 워치에서 카드를 누르면 애플 기본대로 전체 화면 카드와 '아이폰에서 열기'가 뜬다.
6. 끝: 산책을 끝내면 '산책 끝'과 최종값(누운 강아지)을 5분 보여 주고 지운다. 5분 안에 새 산책을 시작하면 끝 카드를 바로 지우고 진행 카드 하나만 둔다(회의 9).
7. 오래된 카드: 30분 넘게 갱신이 없으면 버튼을 없애고 '앱에서 산책을 확인해 주세요'를 보이며, 시간은 마지막 값에서 멈춘다(회의 9). 이때는 기록을 받지 않고, 카드를 누르면 앱이 열린다.
8. 갱신: 시작, 끝, 버튼 기록은 바로, 거리는 10초에 한 번까지(지금 `widgetPushSoon`과 같은 간격). 걸은 시간은 아이폰이 스스로 흐르게 한다.
9. 강아지 자세는 앱과 같은 문턱(0~29 서기, 30~59 킁킁, 60~84 걷기, 85~99 앉기, 100 눕기, 배우는 중은 서기). 카드에서는 움직이지 않는다.
10. 큐는 앱 안 파일에만 두고 백업에서 뺀다(회의 3). UserDefaults를 쓰게 되면 개인정보 파일에 사유(CA92.1)를 더한다.
11. 보이스오버: 버튼은 '똥 기록, 이번 산책 1번', 링은 점수 없이 '산책 중'. 큰 글씨에서는 이름과 횟수를 먼저 지킨다(회의 11).
12. 아이폰 판 번호는 0.5.1, 빌드 번호는 지금 규칙대로.

## 웹(index.html)에서 바꿀 것
- `widgetPush()`의 `update` 값에 산책 링(0~1, 산책 화면 링과 같은 값), 배우는 중 여부, 산책 시작 시각을 더한다. 산책을 시작할 때 한 번 강아지 생김새(`kcLook` 7값)를 더한다. 안드로이드 플러그인이 모르는 값을 무시하는지는 PR #4 코드로 확인한다.
- 눌림마다 아이디, 누른 시각, 그때 카드가 보인 산책의 시작 시각(ws)이 온다. 웹은 기록과 눌림 아이디를 같은 `save()`에 넣고(산책 기록 안 `wgIds`), 저장에 성공한 뒤 `ack(ids)`를 부른다(회의 1). 기록의 시각은 가져간 때가 아니라 누른 때다.
- 앱이 뜰 때와 깨어날 때는 진행 중 산책이 없어도 큐를 읽는다. 눌림은 ws로 산책을 찾아 붙이고, 못 찾은 눌림은 7일이 지나면 버린다(회의 2). 가져가는 사이 새로 들어온 눌림은 ack하지 않아 남는다.
- 되돌리기 눌림은 같은 아이디의 기록을 지운다. 이미 저장한 기록이면 그 기록만 지우고, 아직 안 가져간 눌림이면 둘 다 버린다.
- 카드와 위젯으로 누른 똥은 `f:0`(굳기 미확인)으로 남긴다(지금은 `{f:3, qw:1}`, 3097과 3115). 묽은 변 연속(5795)은 미확인을 건너뛰고(끊지도 더하지도 않음), 평균 굳기(5785, 5801)에서는 뺀다. 똥 목록과 꾹리포트(5790, 5880)는 '굳기 미확인'으로 보인다. 백업 파일을 불러와도 `f:0`이 그대로인지 확인한다.
- 아이폰 플러그인의 `consumeLaunch`는 빈 답을 돌려주고 'launch' 알림은 보내지 않는다(이번 판에 시작 버튼 없음). 앱 타깃 안의 사용자 플러그인은 Capacitor 8 방식으로 등록한다(`patch-ios.js`의 `includePlugins`와 별도).

## 시험
1. 웹(Playwright): 지금 위젯 시험이 그대로 통과하고 새 시험을 더한다. 저장 직후 앱을 다시 켜도 한 건, 같은 눌림을 201번 다시 보내도 한 건, 진행 중 산책 없이 받은 눌림이 맞는 산책에 붙음, 7일 지난 눌림 버림, 23:59에 누르고 다음 날 가져간 눌림의 시각, 가져가는 사이 들어온 눌림이 남음, 되돌리기, 미확인 똥이 묽은 변 연속과 평균에 들어가지 않음, `update`에 링과 배우는 중과 생김새가 있음.
2. 깃허브 액션: 버튼 하나짜리 뼈대로 먼저 플러그인, 인텐트, 큐, `.appex`, 서명을 확인한다(회의 4). 시뮬레이터 빌드에서 `.appex`가 `App.app/PlugIns`에 있는지, 출시 IPA에서 앱과 익스텐션 각각의 서명과 프로비저닝을 본다.
3. 06 아이폰과 워치(테스트플라이트): 산책 시작하면 카드 → 폰을 들어 똥을 눌러 체크까지 3초 안(양손 바꿔서, 인증에 실패한 뒤 다시 눌러도 한 건) → 되돌리기 → 다이내믹 아일랜드 길게 눌러 꾹 → 워치 스마트 스택에서 킁킁 → 끝내면 끝 모습 뒤 사라짐 → 산책 중 앱을 강제로 끄면 30분 뒤 오래된 카드 → 강아지가 앱과 같은 모습.

## 빌더 검토에서 나온 질문과 답 (아스트라, 11/23)
1. 잠금 화면 버튼과 잠금: 애플 문서에 따르면 잠긴 아이폰에서는 카드 버튼이 동작하지 않고, 사람이 인증해 잠금을 풀어야 동작한다. Face ID 아이폰은 쳐다보면 풀려서 바로 누를 수 있고, 다이내믹 아일랜드(잠금이 풀린 상태)는 바로 눌린다. 합격 기준: Face ID 아이폰에서 폰을 들어 체크가 보이기까지 3초 안. 터치 ID 아이폰은 손가락 인증을 포함한다. (사실, 06에게 알림)
2. 정확히 한 번 저장: `drain`은 눌림을 꺼내 주되 지우지 않고, 웹이 기록과 눌림 아이디를 함께 `save()`한 뒤 `ack(ids)`를 부르면 지운다. 웹은 플러그인에 `ack`가 있을 때만 부른다(안드로이드는 지금 그대로). 같은 아이디가 다시 오면 산책 기록 안 `wgIds`를 보고 버린다. (Claude가 정함, 회의 1에서 고침)
3. 애플 워치나 맥에 카드가 따라 보이는 것: 06 본인 기기에 애플이 보여 주는 것이라 '폰 밖으로 보내기'(서버나 다른 사람에게 보내기)로 보지 않는다. 횟수도 보인다. (06 승인, 11/23 밤)
4. 오래된 카드(30분 넘게 갱신 없음): 버튼을 없애고 '앱에서 산책을 확인해 주세요'만 보인다. 이때는 어느 산책인지 모를 수 있어 기록을 받지 않는다. 카드를 누르면 앱이 열린다. (Claude가 정함, 회의 9에서 문구 고침)
5. 끝난 카드의 값: 웹이 산책을 저장한 뒤 최종값(걸은 시간, 거리, 링, 횟수)을 끝 표시와 함께 한 번 더 보낸다. 카드는 그 값을 5분 보여 준다. (Claude가 정함)
6. 링: 산책 화면의 링과 같은 값(이번 산책 점수)이다. 하루 전체 링은 이번 판에서 쓰지 않는다. (Claude가 정함, 앱 화면과 같게)
